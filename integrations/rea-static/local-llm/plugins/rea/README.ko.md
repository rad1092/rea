# REA 분석 실행하기

`REA 분석.command`를 더블 클릭하면 분석할 폴더와 질문, 모델을 순서대로
입력할 수 있습니다. 기존 로컬 AI 앱에서 먼저 켜고, 분석을 마치면 기존
앱에서 정상적으로 꺼 주세요. REA 실행기는 서비스나 모델 설정을 직접
켜거나 바꾸지 않습니다.

이 연결은 **별도 REA 실행 창**입니다. 기존 일반 채팅 화면에서는 REA
도구가 자동으로 호출되지 않습니다. 로컬 모델이 분석 도구를 선택하고
그 결과로 답하는 흐름은 이 실행 창에서 사용할 수 있습니다.

설정에 지정된 분석 루트 안의 JavaScript 폴더 이름을 입력하세요.
절대 경로나 상위 폴더 이동은 사용할 수 없습니다. 현재 분석 루트의
범위는 설치 시 검토한 `runtime/rea.local.json`에 고정되어 있습니다.
다른 위치를 분석하려면 대상 권한과 경로를 검토한 뒤 별도로 설정해야
합니다. 실행 창이 임의로 분석 범위를 넓히지 않습니다.

예를 들어 검증용 폴더가 `app-v1`이면 다음처럼 입력합니다.

```text
분석할 상대 폴더 이름: app-v1
알고 싶은 내용: 정적 분석으로 확인된 구조와 한계를 근거 ID와 함께 설명해 줘.
모델 선택 [1]: 2
```

이 실행 창은 기존 텍스트 클라이언트가 지원하는 현재 기본 모델, MLX Q4,
GGUF Q4를 제공합니다. 일반 앱의 Q8 옵션은 그대로 유지되며, REA 실행
창의 Q8 호출은 아직 연결하지 않았습니다. 모델이 준비되지 않은 경우
기존 브로커의 오류를 표시합니다. 모델을 다운로드하거나 교체하지 않습니다.

이 초기 연결은 정적 분석만 제공합니다. 대상 코드 실행, 디버깅,
Frida, 브라우저 제어, 외부 네트워크 및 기기 접근은 꺼져 있습니다.
깊은 분석이 필요해도 이 경계를 자동으로 바꾸지 않습니다.

터미널에서도 실행할 수 있습니다.

```sh
venvs/broker/bin/python scripts/rea_assistant.py \
  --config runtime/rea.local.json --input app-v1 --model local-qwen-mlx \
  --max-steps 2 '정적 분석 결과를 근거와 함께 요약해 줘.'
```

`Ctrl-C`로 취소하면 REA 연결을 정리합니다. 모델의 정리가 끝났는지는
기존 앱 상태로 확인하세요. 오류나 중단 결과를 분석 완료로 표시하지
않습니다. 실제 근거는 세션마다 분리되며, 종료된 세션의 ID를 다른
실행에서 재사용할 수 없습니다.
